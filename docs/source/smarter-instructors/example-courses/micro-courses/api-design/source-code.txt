Every lecture, lab and assignment in this course rests on the files below, on both sides of one
API: the server in `github.com/smarter-sh/smarter <https://github.com/smarter-sh/smarter>`__, and
the clients in their own repositories. Every reference is to the ``main`` branch, so that students
can open each one during class. Python paths are under ``smarter/smarter/``.

The Server
~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 20 45 35

   * - Topic
     - What Smarter does
     - Where to look
   * - One API for every resource
     - Sixteen commands under ``/api/v1/cli/``: ``apply``, ``validate``, ``get``, ``describe``,
       ``delete``, ``deploy``, ``undeploy``, ``logs``, ``example-manifest``, ``json-schema``,
       ``prompt``, ``status``, ``version``, ``whoami`` and the rest. Each resource-specific
       command takes the kind in the path, and the request body is a YAML manifest.
       :doc:`ADR 006 </adr/006-rest-api>`.
     - `api/v1/cli/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/cli/urls.py>`__,
       `api/v1/cli/views/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/apps/api/v1/cli/views>`__
   * - Three styles side by side
     - Beside the command-style CLI API, each resource family has resource-style DRF endpoints,
       such as ``/api/v1/guardrails/<id>/events/``, and the web console's list pages call a third
       set, authenticated by the session, under ``react-integration/api/``, to list, clone,
       rename and delete. Comparing them is a lesson in API style.
     - `api/v1/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/urls.py>`__,
       `guardrail/api/v1/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/guardrail/api/v1/urls.py>`__,
       `guardrail/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/guardrail/urls.py>`__
   * - From URL to database
     - Each view finds the broker for the kind, and the broker turns the manifest into Django
       models and back. :doc:`ADR 024 </adr/024-broker-model>`.
     - `api/v1/cli/brokers.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/cli/brokers.py>`__,
       `lib/manifest/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/manifest>`__
   * - Versioning
     - The version is in the path (``/api/v1/``) and in every manifest (``apiVersion:
       smarter.sh/v1``). When the ``schema`` command was renamed ``json-schema``, the old path
       was kept as a permanent redirect, because the VS Code extension still calls it.
       :doc:`ADR 023 </adr/023-api-versioning>`.
     - `api/v1/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/urls.py>`__,
       `api/v1/manifests/version.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/manifests/version.py>`__,
       `api/v1/cli/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/cli/urls.py>`__
   * - Authentication
     - API keys built on Django REST Knox. Only a hash of each key is stored, compared in
       constant time, and every key can be deactivated. Every endpoint requires authentication by
       default.
     - `lib/drf/token_authentication.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/drf/token_authentication.py>`__,
       `lib/drf/models.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/drf/models.py>`__,
       `settings/base.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/settings/base.py>`__
       (``REST_FRAMEWORK``)
   * - Errors
     - One base view maps every exception to a status code, and returns it in one JSON format,
       which is also written to the journal. Authentication failures are returned as 403, not
       401: a choice worth reviewing against a style guide.
     - `api/v1/cli/views/base.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/cli/views/base.py>`__,
       `lib/journal/http.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/journal/http.py>`__
   * - Self-description
     - Every kind publishes a JSON Schema and an example manifest through the API, and the whole
       API is described with OpenAPI, in Swagger and ReDoc pages generated by drf-yasg.
     - `api/v1/cli/views/schema.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/cli/views/schema.py>`__,
       `api/v1/cli/views/swagger.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/api/v1/cli/views/swagger.py>`__,
       `docs/urls.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/docs/urls.py>`__
   * - A contract as code
     - The chat API's requests and responses are Pydantic models. Their JSON Schema is exported,
       committed, and tested to be current, and the React chat's TypeScript types are generated
       from it. :doc:`/smarter-framework/smarter-chat/api-contract`.
     - `prompt/contract/models.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/prompt/contract/models.py>`__,
       `chat-contract.schema.json <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/prompt/contract/chat-contract.schema.json>`__
   * - Compatibility as strategy
     - A Proxy passes requests through to a provider's own API, unchanged, so callers keep the
       OpenAI, Anthropic or Gemini SDK and change only the base URL and the key.
       :doc:`/smarter-resources/smarter-proxy`.
     - `apps/proxy/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/apps/proxy>`__,
       `example-manifests/proxies/ <https://github.com/smarter-sh/example-manifests/tree/main/proxies>`__
   * - Limits on abuse
     - Smarter does not configure DRF throttling. Spending and token use are limited by Budgets,
       and middleware blocks clients that probe for missing pages or sensitive files. Students
       can judge whether that is enough.
     - `lib/django/middleware/excessive_404.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/django/middleware/excessive_404.py>`__,
       `user-hourly-token-throttle.yaml <https://github.com/smarter-sh/example-manifests/blob/main/budgets/user-hourly-token-throttle.yaml>`__

The Clients
~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 20 45 35

   * - Client
     - What it shows
     - Where to look
   * - The ``smarter`` CLI
     - A Go command-line client with one subcommand per API command, distributed for macOS,
       Linux and Windows. Its configuration, API key and host override are in one file.
     - `smarter-cli <https://github.com/smarter-sh/smarter-cli>`__,
       `cmd/api.go <https://github.com/smarter-sh/smarter-cli/blob/main/cmd/api.go>`__,
       `cmd/apply.go <https://github.com/smarter-sh/smarter-cli/blob/main/cmd/apply.go>`__
   * - The web console and chat
     - React apps that call the same API with the user's session, and a chat component published
       to npm as ``@smarter.sh/ui-chat``.
     - `smarter/react/packages/ <https://github.com/smarter-sh/smarter/tree/main/smarter/react/packages>`__,
       `smarter.sh-chat <https://github.com/smarter-sh/smarter/tree/main/smarter/react/packages/smarter.sh-chat>`__
   * - The Python SDK
     - A typed client, published to PyPI as ``smarter-api``. It keeps a copy of the platform's
       OpenAPI document, chat and journal contracts and SAM schemas, pinned to a platform release
       and refreshed by a script, generates its manifest models from the schemas, and tests that
       every request it sends matches an operation in the document. Until the copy is refreshed,
       the SDK follows the release it was pinned to, so a breaking change on the platform reaches
       it as a failing contract test.
     - `smarter-python <https://github.com/smarter-sh/smarter-python>`__,
       `smarter/client.py <https://github.com/smarter-sh/smarter-python/blob/main/smarter/client.py>`__,
       `scripts/sync-contracts.sh <https://github.com/smarter-sh/smarter-python/blob/main/scripts/sync-contracts.sh>`__,
       `tests/test_contracts.py <https://github.com/smarter-sh/smarter-python/blob/main/tests/test_contracts.py>`__,
       `ADR 022 <https://github.com/smarter-sh/smarter-python/blob/main/doc/adr/022-pinned-openapi.md>`__
   * - Validation in the editor
     - A VS Code extension that validates manifests against JSON Schemas.
       :doc:`/smarter-framework/vs-code-extension`.
     - `smarter-vscode-yaml <https://github.com/smarter-sh/smarter-vscode-yaml>`__
