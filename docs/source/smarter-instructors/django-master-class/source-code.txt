Every lecture, lab and assignment in this course rests on the files below. Every reference is to
the ``main`` branch of `github.com/smarter-sh/smarter <https://github.com/smarter-sh/smarter>`__,
so that students can open each one during class. Python paths are under ``smarter/smarter/``.

Configuration and Startup
~~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 22 43 35

   * - Module
     - What to read
     - Where to look
   * - 1. Django, 12-Factor and settings
     - Every setting is read from the environment, validated and typed by a Pydantic ``Settings``
       class, and only then copied into Django's settings. One settings module per environment
       inherits from ``base.py``. :doc:`ADR 004 </adr/004-12-factor>`,
       :doc:`ADR 007 </adr/007-settings>`.
     - `common/conf/settings.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/conf/settings.py>`__,
       `common/conf/env.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/conf/env.py>`__,
       `common/conf/defaults.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/conf/defaults.py>`__,
       `settings/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/settings>`__,
       `.env.example <https://github.com/smarter-sh/smarter/blob/main/.env.example>`__
   * - 2. The startup sequence
     - Every app's ``ready()`` imports its signals and receivers. The database may not be
       reachable, or migrated, when ``ready()`` runs, so Waffle checks first. The cache is
       resolved lazily, so that Django does not fall back to a local-memory cache when
       ``django.core.cache`` is imported too early.
     - `apps/dashboard/apps.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/dashboard/apps.py>`__,
       `lib/django/waffle/ready.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/django/waffle/ready.py>`__,
       `lib/cache/lazy_cache.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/cache/lazy_cache.py>`__,
       `common/mixins/helper_mixin.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/mixins/helper_mixin.py>`__
       (``SmarterReadyState``)
   * - 3. Python logging
     - A logger factory, loggers switched on per subsystem by Waffle, a filter, a middleware that
       adds the user to every record, and a handler that publishes records to Redis.
       :doc:`ADR 011 </adr/011-logging>`.
     - `lib/logging/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/logging>`__
       (``get_smarter_logger.py``, ``waffle_switched_logger.py``, ``filters.py``,
       ``middleware.py``, ``redis_log_handler.py``)

The Request
~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 22 43 35

   * - Module
     - What to read
     - Where to look
   * - 4. The request and the middleware chain
     - The ``MIDDLEWARE`` list, commented block by block, and the order in which each class sees
       the request and the response. ``SmarterRequestMixin`` reads what middleware attached to
       the request. A diagnostic middleware checks what every class in the chain returns.
     - `settings/base.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/settings/base.py>`__
       (``MIDDLEWARE``),
       `lib/django/request.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/django/request.py>`__,
       `common/utils/request.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/utils/request.py>`__,
       `lib/django/middleware/debug.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/django/middleware/debug.py>`__
   * - 5. Writing middleware
     - A shared base class, replacements for Django's CORS, CSRF and security middleware, an API
       key authentication middleware, and middleware that blocks probes for sensitive files and
       bursts of 404s.
     - `lib/django/middleware/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/django/middleware>`__,
       `common/mixins/middleware_mixin.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/mixins/middleware_mixin.py>`__,
       `lib/drf/middleware.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/drf/middleware.py>`__,
       `apps/llmclient/middleware/security.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/llmclient/middleware/security.py>`__
   * - 6. Many hosts; Waffle
     - ``django-hosts`` maps the console, the API and each chatbot's host to its own URLconf.
       Waffle switches are declared once, created on first use, and checked safely before the
       database is ready. :doc:`ADR 022 </adr/022-feature-flags>`.
     - `hosts.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/hosts.py>`__,
       `urls/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/urls>`__,
       `lib/django/waffle/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/django/waffle>`__
       (``switches.py``, ``is_active.py``)

Data

   :widths: 22 43 35

   * - Module
     - What to read

   * - 7. Customizing the ORM
     - Abstract base models for timestamps and metadata (name, description, version, tags and
       annotations), and generic querysets and managers whose methods return the subclass's own
       types.
       :doc:`ADR 017 </adr/017-database>`.
     - `lib/django/models/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/django/models>`__
       (``timestamped_model.py``, ``metadata_model.py``),
       `apps/account/models/user_profile.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/account/models/user_profile.py>`__
       (``SmarterBaseQuerySetWithPermissions``, ``SmarterBaseModelManager``)
   * - 8. The user; ownership and sharing
     - Smarter keeps Django's ``User`` and adds a ``UserProfile`` that joins a user to an account.
       Every resource inherits an owner, and its manager filters by what a user owns, what is
       shared with them, and what they may change.
     - `apps/account/models/user_profile.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/account/models/user_profile.py>`__,
       `apps/account/models/metadata_with_ownership.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/account/models/metadata_with_ownership.py>`__,
       `apps/account/mixins.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/account/mixins.py>`__,
       `common/enum.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/common/enum.py>`__
       (``SmarterResourceOwnershipFilterEnum``)
   * - 9. Signals and receivers
     - Every app declares its own signals in ``signals.py`` and handles them in ``receivers.py``,
       for logging, cache invalidation, the journal and prompt progress.
     - `apps/llmclient/signals.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/llmclient/signals.py>`__,
       `apps/llmclient/receivers.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/llmclient/receivers.py>`__,
       `lib/drf/receivers.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/drf/receivers.py>`__,
       `lib/journal/receivers.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/journal/receivers.py>`__

Asynchrony and Redis
~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 22 43 35

   * - Module
     - What to read
     - Where to look
   * - 10. Caching complex objects
     - A decorator that builds a deterministic key from a function's arguments, caches ``None``
       correctly with sentinels, and gives each function an ``.invalidate()``. Cached querysets
       of API keys, invalidated by receivers. :doc:`ADR 018 </adr/018-caching>`.
     - `lib/cache/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/cache>`__
       (``decorators.py``, ``cache_sentinel.py``, ``lazy_cache.py``),
       `lib/drf/caching.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/drf/caching.py>`__
   * - 11. Celery and Celery Beat
     - One Celery app, two queues with a worker each, and a Beat schedule that names each task's
       queue. :doc:`ADR 009 </adr/009-async-tasks>`, :doc:`ADR 030 </adr/030-task-queues>`.
     - `lib/celery_conf/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/lib/celery_conf>`__,
       `workers/ <https://github.com/smarter-sh/smarter/tree/main/smarter/smarter/workers>`__
       (``celery.py``, ``celerybeat.py``),
       `apps/prompt/tasks.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/prompt/tasks.py>`__,
       `docker-compose.yml <https://github.com/smarter-sh/smarter/blob/main/docker-compose.yml>`__
   * - 12. ASGI and publish-subscribe
     - The ASGI application routes HTTP and WebSockets. A prompt runs in a worker thread while an
       async generator streams its progress as Server-Sent Events, forwarded from signals through
       a ``ContextVar``. Log records are published to Redis channels and streamed to the browser.
     - `asgi.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/asgi.py>`__,
       `consumers.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/consumers.py>`__,
       `apps/prompt/progress.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/prompt/progress.py>`__,
       `lib/logging/redis_log_handler.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/lib/logging/redis_log_handler.py>`__,
       `terminal_emulator/api/streams.py <https://github.com/smarter-sh/smarter/blob/main/smarter/smarter/apps/dashboard/views/terminal_emulator/api/streams.py>`__

       :doc:`ADR 006 </adr/006-rest-api>`, :doc:`ADR 023 </adr/023-api-versioning>`,

   * - 14. OAuth
     - Google and GitHub sign-in with Python Social Auth, a pipeline with Smarter's own steps for
