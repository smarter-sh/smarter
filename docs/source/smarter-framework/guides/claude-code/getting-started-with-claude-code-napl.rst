Getting Started with Claude Code and Smarter at NAPL
====================================================

Part 1 — Adding Anthropic as an LLM Provider
=============================================

Goal
----

Add Anthropic as a new LLM provider in Smarter so that approved Claude
models can be made available to Northern Aurora Power & Light (NAPL)
programmers and other Smarter resources.


Prerequisites
-------------

Before adding Anthropic to Smarter, confirm that you have:

* A running and accessible Smarter platform.
* Administrator-level access to manage providers.
* The Smarter CLI installed and configured.
* An Anthropic account with API access and a valid API key.
* Familiarity with YAML and command-line tools.


Concept Overview
----------------

Smarter manages AI resources using declarative YAML files called
**Smarter API Manifests (SAM)**. A manifest describes the desired
configuration of a Smarter resource and is applied using the Smarter CLI.

For this workflow, the key components are:

* **Anthropic** — The external LLM provider that supplies Claude models.

* **Provider** — The Smarter resource that represents an external LLM
  provider and stores the configuration Smarter needs to connect to it.

* **Provider credential** — The credential Smarter uses to authenticate
  to Anthropic. This credential should be managed centrally and must not
  be committed to source control.

* **Provider manifest** — A YAML document that describes the Anthropic
  Provider configuration.

* **Smarter CLI** — The command-line interface used to generate, apply
  and inspect Smarter resources.

A Provider manifest follows the standard Smarter manifest structure:

``apiVersion``
   Identifies the Smarter manifest API version.

``kind``
   Identifies the resource type. For this workflow, the kind is
   ``Provider``.

``metadata``
   Contains identifying information such as the resource name and
   description.

``spec``
   Contains the Provider-specific configuration.


Step-by-Step
------------

Step 1 — Obtain an Anthropic API Key
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Sign in to the Anthropic Console and create an API key for the Smarter
integration.

Use a descriptive name that identifies its purpose, for example
``smarter-napl-prod``.

.. warning::

   Treat the Anthropic API key as a secret. Do not commit it to Git or
   include it in documentation.


Step 2 — Make the Anthropic Credential Available to Smarter
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Smarter requires an Anthropic credential so that it can authenticate to
the provider.

The current Smarter documentation identifies the deployment setting as:

.. code-block:: text

   SMARTER_ANTHROPIC_API_KEY=<Anthropic API key>

Configure this value using the credential-management method established
for your Smarter deployment.

The Anthropic API key is a platform credential. Individual programmers
should not need access to it.


Step 3 — Generate a Provider Manifest
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Use the Smarter CLI to generate an example Provider manifest:

.. code-block:: console

   smarter manifest provider

Use the generated output as the starting point for the Anthropic Provider
configuration.

.. important::

   Use the manifest generated by the installed version of Smarter as the
   authoritative template because Provider manifest fields may change
   between releases.


Step 4 — Configure the Anthropic Provider
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Edit the generated manifest with the Anthropic-specific information
required by the template.

The configuration should identify Anthropic as the provider and include
the information Smarter requires to connect to and verify the provider.

Do not place the Anthropic API key directly in a manifest that will be
committed to source control.


Step 5 — Apply the Provider Manifest
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Apply the completed manifest with the Smarter CLI:

.. code-block:: console

   smarter apply -f <anthropic-provider-manifest>.yaml

Smarter validates the manifest and creates or updates the Provider
resource based on the declared configuration.


Step 6 — Verify the Provider
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Inspect the Provider after the manifest has been applied:

.. code-block:: console

   smarter describe provider <provider-name>

Review the returned Provider information and status to confirm that the
resource exists and that provider verification has completed successfully.


Proof of Concept
----------------

Run the following command using the name of the Anthropic Provider that
you created:

.. code-block:: console

   smarter describe provider <provider-name>

A successful result should confirm that:

* the Provider exists in Smarter;
* the returned configuration identifies Anthropic as the provider; and
* the Provider reports a successful verification state.

If these conditions are met, Smarter has accepted the Anthropic Provider
configuration and the provider is available for use by supported Smarter
resources.


Troubleshooting
---------------

**The Provider manifest is rejected**
   Generate a fresh template with ``smarter manifest provider`` and compare
   it with your file. Check the YAML structure, indentation and required
   fields.

**The Provider cannot authenticate to Anthropic**
   Confirm that the Anthropic API key is valid and that it has been made
   available to the Smarter deployment using the configured credential
   management method.

**The Provider does not appear after applying the manifest**
   Confirm that the Smarter CLI is connected to the intended environment
   and that your account has administrator-level permissions.

**The Provider fails verification**
   Run ``smarter describe provider <provider-name>`` and review the returned
   Provider information. Recheck the Anthropic credential and the Provider
   configuration before retrying.


Part 2 — Getting Started with Claude Code
==========================================

.. note::

   Claude Code integration with Smarter is currently documented as a
   prerelease feature and may change in future Smarter releases.


Goal
----

We will use Claude Code with Smarter to open a local project and ask
Claude Code to explain an existing source file, confirming that the
developer workstation is configured to use the centrally managed
Smarter service.


Prerequisites
-------------

This tutorial assumes that you:

* Have an active Smarter account and already know how to log in.
* Are comfortable working from a terminal or command-line shell.
* Are familiar with Git and working with a local source-code repository.
* Can configure environment variables or application settings on your
  workstation.
* Have access to the Smarter environment and endpoint provided by your
  organization.
* Have permission to install Claude Code on your workstation.

The Anthropic provider is assumed to have already been configured in
Smarter by an administrator. You do not need a separate Anthropic API key
for this tutorial.


Setup
-----

Complete the following workstation setup before starting the tutorial.

1. Install the Smarter CLI
~~~~~~~~~~~~~~~~~~~~~~~~~~

Install the Smarter CLI for your operating system using the instructions
provided by Smarter:

``https://smarter.sh/cli``

Confirm that the CLI is available:

.. code-block:: console

   smarter version


2. Obtain Your Smarter Access Information
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Obtain the following information from your NAPL Smarter administrator:

* Your Smarter API key.
* The Smarter environment or endpoint you should use.
* Any account information required by your organization's Smarter
  configuration.

The Smarter API key identifies and authenticates you to Smarter. It is
different from the Anthropic API key configured by the administrator in
Part 1.

.. warning::

   Treat your Smarter API key as a credential. Do not commit it to Git or
   include it in source code.


3. Configure the Smarter CLI
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Run the Smarter CLI configuration command:

.. code-block:: console

   smarter configure

Enter the Smarter environment and account information supplied by your
administrator.

Verify that the CLI can authenticate to Smarter:

.. code-block:: console

   smarter whoami

A successful response confirms that your workstation can authenticate to
the Smarter platform.


4. Install Claude Code
~~~~~~~~~~~~~~~~~~~~~~

Install Claude Code using the installation method documented for your
workstation.

The current Smarter Claude Code guide shows the following installation
command:

.. code-block:: console

   npm install -g @anthropic-ai/claude-code

Confirm the installation:

.. code-block:: console

   claude --version


5. Obtain the Smarter Gateway Configuration
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Claude Code must be configured to send its requests through the Smarter
service rather than directly to Anthropic.

Obtain the Smarter gateway URL from your administrator. The current
Smarter Claude Code documentation uses the following configuration
variables:

``ANTHROPIC_BASE_URL``
   The Smarter gateway endpoint.

``ANTHROPIC_AUTH_TOKEN``
   Your Smarter authentication token.

Use the gateway URL and credential values provided for your NAPL
environment. Do not substitute the centrally managed Anthropic API key.


Concept Overview
----------------

In the documented Smarter integration, Claude Code does not connect
directly to Anthropic. Instead, it is configured to send requests through
the Smarter gateway.

The main components are:

``Claude Code``
   The programmer-facing command-line coding assistant running on the
   local workstation.

``Smarter``
   The centrally managed platform that receives authenticated requests
   from Claude Code and connects them to the configured LLM provider.

``Smarter API key``
   The programmer's credential for authenticating to Smarter. This is not
   an Anthropic API key.

``Anthropic``
   The external LLM provider configured centrally in Smarter.

``Claude model``
   The Anthropic model that ultimately processes the programmer's request.

The documented request flow is:

.. code-block:: text

   Programmer
       |
       v
   Claude Code
       |
       |  ANTHROPIC_BASE_URL = <Smarter gateway>
       |  ANTHROPIC_AUTH_TOKEN = <Smarter API key>
       v
   Smarter
       |
       |  Centrally managed Anthropic credential
       v
   Anthropic / Claude
       |
       v
   Response returned through Smarter to Claude Code

This separation allows programmers to use Claude Code without receiving
or managing the organization's Anthropic API credential. Provider
configuration remains an administrative responsibility, while programmers
authenticate to Smarter using their own Smarter credentials.


Step-by-Step
------------

Step 1 — Configure Claude Code to Use Smarter
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Claude Code must be configured to send its requests to the Smarter gateway
rather than directly to Anthropic.

The current Smarter Claude Code documentation uses the following environment
variables:

``ANTHROPIC_BASE_URL``
   The Smarter gateway URL supplied by your administrator.

``ANTHROPIC_AUTH_TOKEN``
   Your personal Smarter API key.

Claude Code settings can be stored in its ``settings.json`` file. For
example:

.. code-block:: json

   {
     "env": {
       "ANTHROPIC_BASE_URL": "<SMARTER_GATEWAY_URL>",
       "ANTHROPIC_AUTH_TOKEN": "<YOUR_SMARTER_API_KEY>"
     }
   }

Typical locations are:

* Linux/macOS: ``~/.claude/settings.json``
* Windows: ``%USERPROFILE%\.claude\settings.json``

Replace the placeholders with the values provided by your Smarter
administrator.

.. warning::

   ``ANTHROPIC_AUTH_TOKEN`` contains your Smarter credential, not the
   Anthropic API key configured in Part 1. Do not commit this file or expose
   the credential in source control.


Step 2 — Open a Local Project
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Open a terminal and change to a small local source-code project that is
safe to use for the initial test:

.. code-block:: console

   cd <path-to-your-project>

For the first test, use a project that does not contain sensitive or
production data.


Step 3 — Start Claude Code
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Start Claude Code from the project directory:

.. code-block:: console

   claude

Claude Code should start with the project directory available as its
working context.


Step 4 — Give Claude Code a Small Programming Task
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Start with a narrowly scoped task that is easy to review.

For example:

.. code-block:: text

   Explain the purpose of the main source file in this project and identify
   one small improvement you would recommend. Do not modify any files.

Review the response and confirm that it refers to the source code in the
project rather than returning only a generic programming explanation.


Step 5 — Try a Controlled Code Change
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

After confirming that Claude Code can inspect the project, give it a small
programming task appropriate for the repository.

For example:

.. code-block:: text

   Add a short comment explaining the purpose of the main function. Show me
   the proposed change before modifying the file.

Review the proposed change before allowing it to be applied.


Step 6 — Review and Test the Result
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Treat Claude Code output as a development suggestion rather than
automatically approved code.

Review any proposed changes, run the project's normal tests or validation
process, and inspect the Git diff before committing anything.


Proof of Concept
----------------

The setup is successful when Claude Code can start from the local project
directory and respond to a project-specific programming request through
the configured Smarter gateway.

For example, start Claude Code:

.. code-block:: console

   cd <path-to-your-project>
   claude

Then enter:

.. code-block:: text

   Explain the purpose of the main source file in this project and identify
   one small improvement you would recommend. Do not modify any files.

A successful result should:

* reference code or files from the local project;
* provide a relevant explanation rather than a generic response; and
* return the response without requiring the programmer to provide an
  Anthropic API key directly.

For an additional validation, ask Claude Code to propose a small code
change and review the resulting diff before accepting or committing it.


Troubleshooting
---------------

**Claude Code cannot reach the Smarter service**
   Confirm that ``ANTHROPIC_BASE_URL`` points to the Smarter gateway URL
   supplied by your administrator. Also confirm that your workstation has
   network access to the Smarter environment.

**Authentication fails**
   Confirm that ``ANTHROPIC_AUTH_TOKEN`` contains your Smarter API key and
   not the Anthropic API key configured by the platform administrator.

**The ``claude`` command is not found**
   Confirm that Claude Code is installed and available on your system
   ``PATH``. Run ``claude --version`` to verify the installation.

**Claude Code starts but returns an unexpected provider or connection error**
   Confirm that Anthropic is available in Smarter and that the provider
   configuration from Part 1 has been successfully verified. If you do not
   administer the platform, contact the Smarter administrator.

**The response does not appear to understand the local project**
   Confirm that Claude Code was started from the intended project directory.
   Use a specific prompt that references a file or function in the project
   rather than a general programming question.

**A proposed code change is incorrect**
   Do not accept the change automatically. Review the proposed diff, refine
   the prompt if necessary, and run the project's normal tests or validation
   process before committing the change.
