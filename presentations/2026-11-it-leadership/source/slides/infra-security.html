For infrastructure

Security architecture

Network

Private subnets for data and compute. HTTPS-only ingress; no SSH needed on EKS. A DNS record and TLS certificate per host, never wildcards.

Credentials

Encrypted Secret vault. Models never receive credentials, and provider keys are never handed to teams.

Application

Guardrails for PII, secrets, prompt injection, jailbreaks and code injection. Rate limits per user and IP. No execution of model-generated code.

Audit

The Smarter Journal persists every API response. Every prompt traces back to its account and budget.

About 3 minutes. This slide will draw the most questions from security-minded attendees. Network: the reference deployment puts the database and compute in private subnets, exposes only HTTPS through the load balancer and ingress, and needs no SSH access to hosts. Each deployed assistant gets its own DNS record and certificate; Smarter deliberately avoids wildcard DNS to prevent subdomain takeover. Credentials: secrets are encrypted at rest and resolved server-side, so neither the model nor the end user ever sees them. Application: deterministic guardrails screen input and output; every API is rate limited (defaults 600 per minute per user, 120 per minute per anonymous IP); custom middleware blocks probing for sensitive files and floods of 404s; and tools are declared, typed calls rather than code execution. Audit: the Journal is designed for long-term, read-optimized storage of every API response. Note the boundaries too: Smarter relies on your cloud for firewalling, WAF, encryption of storage volumes and malware scanning.
